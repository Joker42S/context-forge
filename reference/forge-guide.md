# AI 资产精炼指南

> 本文件是 Context Forge 的精炼阶段参考规范：分类定义、判定规则、精炼规则与质量检查。工作流、落盘与汇报见 `SKILL.md`；文件格式见 `templates/`。

## 分类定义

### Prompt —「怎么说」

给人复制粘贴使用：单轮内可直接使用的指令模板。

必须包含：适用场景、可直接复制的 Prompt 正文、变量、输入要求、输出格式、约束。

单条口号或零散话术不算 Prompt；给 agent 自动加载的方法应归 Skill。

### Skill —「怎么做」

给 agent 作为 skill 加载：多步骤、可执行、带判断标准的工作方法。

必须包含：目标、触发条件、前置输入、步骤、判断标准、检查清单、异常处理。

只有「让 AI 认真分析」这类空泛指令不算 Skill。

### Knowledge —「依据什么」

组织特有、AI 难以可靠获得的事实与上下文：业务规则、术语缩写、流程例外、系统架构、决策记录、踩坑经验、数据口径、权限合规、权威源索引。

- 只写事实，不写建议。踩坑经验若形态是可执行检查步骤，归 Skill。
- 引用通用公开文档时，只记录「权威源 + 适用版本 + 内部适配点」，不抄录原文。
- 无内部适配点的通用内容不收录，在汇报中说明原因即可。

## 判定规则

1. 一级判据是「谁来用」：人复制粘贴 → Prompt；agent 自动加载 → Skill；作为依据被引用 → Knowledge。
2. 多步骤、可执行、带判断标准是 Skill 的辅助特征，不是 Prompt 与 Skill 的分界线——Prompt 正文可以含编号步骤，只要它整体是单轮粘贴使用的模板。
3. 同一内容同时含背景事实和可执行方法时拆开：事实进 Knowledge，方法进 Prompt 或 Skill，用 `related` 互链，不硬归一类。
4. 通用内容是否值得入库，判据是有无内部适配点：有则 Knowledge 化（记录权威源与适配点），无则不收录。

## 精炼规则

1. 只基于上下文精炼，不编造外部事实。合理归纳标注「归纳」；不确定标「待确认」。
2. 原子化：每条只表达一个可复用单元；合并重复内容。
3. 命名：`name` 用人读名（Prompt / Skill 用 `场景-动作-对象`，Knowledge 用 `场景-对象`）；`slug` 与文件名用英文或拼音的小写 kebab-case。
4. 每条资产必须给出：来源（上下文哪段 / 原句摘要）、置信度（high / medium / low，对应高 / 中 / 低）、适用范围或时效（未知写「未知」）。
5. 某类没有内容就写「无」，不要硬凑。
6. 不输出空泛总结、励志话术、无来源摘抄。

## 质量检查

产出后逐项检查：

- **分类错误**：归类是否符合判定规则。
- **重复 / 可合并**：与已有资产是否语义重复或部分重叠。
- **空泛 / 不可执行**：Prompt 是否可直接复制使用，Skill 是否可执行、有判断标准。
- **可能编造**：有无上下文中不存在的事实，归纳与推断是否已标注。
- **自包含**：有无「见上文」、会话临时 ID 之类的悬空引用。
